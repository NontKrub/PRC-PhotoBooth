## Release Invariants

- A guest receives media only when the current camera attempt has a proven freshness boundary.
- A durable finalization generation owns its complete desired job bundle. Jobs and dependencies cannot cross transaction IDs.
- Uncertain printer submission remains sideEffectUnknown; no automatic retry may duplicate a print.
- Socket liveness, timeout, connection invalidation, slot release, and actual reconnect initiation continue while MainActor is blocked.
- A trusted candidate receives an admission opportunity only. Cryptographic authentication remains required.
- Ambiguous local network selection disables local guest delivery and explains the cause.
- Production Pipeline soak uses the production coordinator, persistence, camera, finalization, queue, and configured delivery path.
- Only manifests marked origin=soakTest for the active run may be cleaned by soak cleanup.
- A partial or failed run never displays a passed result. Synthetic benchmark coverage is identified as synthetic.

## Finding Status

### A01 — DSLR cross-guest recovery privacy (P0)

- **Root cause:** A failed transfer discarded the capture context needed by Retry Receive. Recovery then lacked the identity of the shutter attempt and could fall through to a “latest media” path.
- **Fix:** Separate active and recoverable attempt contexts; retain immutable request-time, baseline file names and handles, camera identity, and freshness bounds after recoverable failure. Invalidate that context at explicit lifecycle boundaries. Validate media discovered through filesystem polling, PTP ObjectAdded, and the fixed Sony PC buffer against the same attempt. Baseline acquisition fails closed.
- **Invariant:** A transfer with unproven camera identity or freshness is rejected; older guest media is never selected as a fallback.
- **Tests:** DSLRCaptureAttemptTests covers recovery-context lifecycle, camera identity, baseline acquisition, stale filenames/handles, late transfer, object-added freshness, and PC-buffer behavior. All tests passed in the final 590-test Xcode 26.6 Mac run.
- **Manual verification:** Still required with a Sony ZV-E10 containing older SD-card images: fail transfer, Retry Receive, Retake, disconnect/reconnect, and power-cycle. Confirm no prior guest image is displayed or persisted.
- **Status:** Implemented — focused automated tests passed on Xcode 26.6 — physical Sony verification pending.

### A02 — Authoritative finalization transaction (P1)

- **Root cause:** The UI and durable manifest could disagree after finalization enqueue failure; reconciliation could omit desired jobs or accept jobs from a stale generation.
- **Fix:** Persist FinalizationPlan and its transaction ID with the manifest; batch the desired job bundle; enforce transaction ownership at execution and dependency checks; reconcile missing jobs without rolling a finalizing manifest back to capturing. Preserve ambiguous print submissions as operator-resolved unknown outcomes. Legacy manifests and uncertain legacy print jobs are handled conservatively.
- **Invariant:** One completed capture sequence has one authoritative finalization generation. Old jobs cannot operate on current content or satisfy current dependencies. UI remains processing after durable finalization.
- **Tests:** FinalizationTransactionTests, JobQueueStoreTests, JobRecoveryTests, SessionRecoveryTests, and SessionJobQueueTests cover durable intent, transaction mismatch, repair, dependency isolation, required-job recovery, and unknown print behavior. All tests passed in the final 590-test Xcode 26.6 Mac run.
- **Manual verification:** Force quit during capture, finalizing, render, upload, and print; restart and inspect manifest/job ownership. For uncertain CP1500 submission, verify operator resolution and no automatic duplicate.
- **Status:** Implemented — focused automated tests passed on Xcode 26.6 — full suite and physical restart/print fault verification pending.

### A03 — Production transport recovery off MainActor (P1)

- **Root cause:** The transport facade is MainActor-isolated. Previously, a Mac control listener handed sockets to MainActor before admission, and reconnect timer expiry handed off before creating and starting a replacement socket.
- **Fix:** The Mac control listener now reserves/rejects a single control slot on the Network queue, starts accepted sockets there, and expires unadopted admissions with a bounded queue timer. A cached reconnect route now creates and starts the replacement NWConnection on that queue, retries at most five times, and times out sockets that remain waiting or are not adopted within ten seconds. Control socket failures release the slot on the Network queue.
- **Invariant still open:** Route discovery/browser result selection and its initial browser-driven connection still cross MainActor. The production UI/authentication facade also adopts the started connection on MainActor. These paths need further ownership work and device verification.
- **Tests:** productionListenerAdmissionIsQueueOwned proves a real loopback listener can accept a second connection after its first unadopted admission expires during a MainActor stall. productionReconnectStartsSocketOffMainActor proves a cached replacement socket reaches a real loopback listener during a MainActor stall. NetworkRouteTests and BoothPreAuthPolicyTests passed twice consecutively; the complete 590-test Mac suite also passed on Xcode 26.6.
- **Manual verification:** Block MainActor while dropping Wi-Fi/Ethernet and confirm browser-driven route discovery, authentication, and recovery with the production iPad. Confirm waiting/retry behavior across Wi-Fi and wired Ethernet.
- **Status:** Partially fixed — listener admission and cached socket start are automated on the Network queue — browser discovery and physical verification remain P1 release blockers.

### A04 — Trusted reconnect under pre-auth abuse (P1)

- **Root cause:** A global anonymous pre-auth failure ceiling can prevent an iPad from reconnecting after a LAN flood. Trust decisions must not rely on claimed Bonjour identity or source IP.
- **Fix so far:** Admission state and the limiter now run on the Network queue. An endpoint previously observed only after successful cryptographic authentication, and still belonging to a trusted peer, gets a preferred admission opportunity that bypasses the anonymous global ceiling. Preferred status may replace one untrusted, unauthenticated control slot. It never authenticates the connection; the existing secure negotiation and stored-secret HMAC proof remain required.
- **Invariant still open:** The preferred lane is based on a previously authenticated source endpoint, not a bounded cryptographic identity probe. A paired iPad connecting from a new address after DHCP/network changes does not yet have the reserved identity-probe path. The source address remains an admission hint only.
- **Tests:** trustedEndpointAdmissionSurvivesAnonymousFlood covers the runtime flood ceiling and preferred admission. Existing BoothPairingTests cover HMAC acceptance with the paired secret and rejection of a wrong secret. These and all other tests passed in the 590-test Mac run. A real listener test with 100 invalid authentication attempts followed by trusted stored-secret reconnect is still pending.
- **Manual verification:** With a paired production iPad, send at least 100 invalid pairing/authentication attempts, then reconnect using both its previous and a changed address. Confirm the stored-secret proof succeeds and anonymous clients remain throttled.
- **Status:** Partially fixed — queue-owned admission and known-endpoint recovery are tested — cryptographic identity-probe and 100-attempt production integration remain a P1 release blocker.

### A05 — Customer display authority and recovery

- **Root cause:** Fresh-session and recovered-session flows had inconsistent decisions about whether an iPad or external viewer was authoritative.
- **Fix:** CustomerDisplayAuthority applies one authority matrix to none, iPad-only, external-only, and dual-display configurations.
- **Invariant:** A session advances only through the authoritative display path available for its current state.
- **Tests:** CustomerDisplayWorkflowTests covers the authority matrix. Recovery integration should be exercised with the physical display matrix during device testing.
- **Manual verification:** Test iPad only, external display only, both, and neither during fresh start and recovery.
- **Status:** Implemented with matrix test coverage. Physical display/recovery checks pending.

### A06 — Authoritative guest delivery endpoint (P1)

- **Root cause:** Choosing the first or lowest-numbered private interface can select a VPN/bridge or the wrong link when Wi-Fi and Ethernet are both active.
- **Fix:** Model a typed endpoint containing interface name/index/type/address/port. Automatic selection fails closed when multiple candidates remain. Explicit Wi-Fi, Ethernet, or interface choices constrain resolution; supported direct-Ethernet addresses are considered only for the Ethernet choice. Coordinator QR, preflight, and job execution use the same selection. Unavailable or ambiguous local HTTP contributes no URL to QR policy.
- **Invariant:** No localhost, arbitrary private interface, or interface-name heuristic is emitted in a guest QR. When route identity is uncertain, local delivery is unavailable.
- **Tests:** GuestDeliveryEndpointResolverTests covers ambiguous paths, explicit Wi-Fi/Ethernet, direct Ethernet, interface identity, port, and unavailable resolution. SessionQRCodePayloadResolverTests covers loopback/insecure failures. All tests passed in the final 590-test Xcode 26.6 Mac run.
- **Manual verification:** Test Wi-Fi only, Ethernet only, both, VPN active, VM interfaces installed, route change, and the actual guest network adapter. Scan each QR from a guest device.
- **Status:** Implemented with fail-closed resolution — automated tests passed on Xcode 26.6 — physical network matrix pending.

### A07 — Bounded local HTTP admission and recovery (P2)

- **Root cause:** A large number of simultaneous sockets could consume server resources; per-client state could outlive the connection or fail to release on timeout.
- **Fix:** Lease-token admission enforces global and per-client caps; IPv4-mapped IPv6 addresses normalize to the same client identity. A lease is released exactly once when a request completes, fails, or times out. Slow/no-data requests have a bounded timeout and overflow receives 503.
- **Invariant:** One guest cannot exhaust all local HTTP slots indefinitely; lease accounting cannot underflow or retain idle client records.
- **Tests:** LocalWebServerTests includes production HTTP overflow/route checks, raw slow-client timeout cleanup, exact-once lease release, global cap, and address normalization. All tests passed in the final 590-test Xcode 26.6 Mac run.
- **Manual verification:** Exercise 20–50 concurrent guest downloads and slow clients while confirming normal health and guest routes recover.
- **Status:** Implemented — automated tests passed on Xcode 26.6 — physical load verification pending.

## Event Readiness / Soak

The Settings screen now exposes three explicit modes:

- **Synthetic Benchmark:** generated images, isolated scratch files, compositor timing, and locally claimed/completed benchmark queue records. It says that it does not validate the production workflow.
- **Camera Hardware:** requires the selected live camera and rejects demo mode. It captures real images and fails on capture errors; it creates no customer sessions.
- **Production Pipeline:** requires a live BoothCoordinator, active event, ready camera and customer display, available production persistence, settled queue, server, and an unambiguous configured guest delivery path. It uses the current event's template and photo count, starts origin-tagged sessions, accepts captures through the ordinary review handler, finalizes through the production transaction/queue, and verifies configured delivery.

Production sessions carry origin=soakTest, soakRunID, and soakCycleIndex. Normal session starts and active-event switches are blocked while the run owns the booth. Cleanup checks origin, run ID, completed status, and the active run before removing only that soak session's gallery entry, server token, workspace, queue records, manifest, and local session record. With cleanup disabled, completed records remain. Failed/cancelled sessions are not silently cleaned.

Cloud upload is an explicit Production Pipeline option using the current production settings. Physical printing is disabled by default and only available in Production Pipeline. When enabled, confirmation states the maximum job count and interval; cycle 1 and then every Nth cycle submit real print jobs. The production cycle fails if an explicitly scheduled print or requested cloud job is not present and successful.

Outcomes distinguish passed, failed, stoppedEarly, and cancelled. Only all requested, error-free cycles can pass. Subsystem coverage labels unexercised hardware as NOT TESTED. RSS is reported as baseline/peak/final and growth; the report does not infer that no leak exists. Camera reconnects are run-scoped when a live coordinator is supplied. iPad model compatibility and the physical event network are not established by simulator or synthetic tests.

Automated runner coverage does not replace a hardware-backed production soak. SoakTests exercises synthetic benchmark execution, missing hardware/coordinator rejection, queue claiming, stop/cancel outcomes, report coverage, and legacy mode decoding. An end-to-end 500-session production soak remains unrun.

Do not count a synthetic benchmark toward release soak. On production Mac hardware:

1. Connect Sony ZV-E10, Canon SELPHY CP1500, production iPad (include an older iPad Pro 9.7-class device where available), Ethernet adapters/cables, and event Wi-Fi/hotspot.
2. Complete **500 successful Production Pipeline sessions** and a continuous **4–6 hour** run. Export the report and retain the logs. Confirm every enabled subsystem is PASS; any disabled/unavailable subsystem remains NOT TESTED.
3. During the camera run, test disconnect/reconnect, busy camera, delayed transfer, transfer timeout, old SD-card images, failed capture + Retry Receive, failed capture + Retake, Sony PC-buffer behavior, and camera power cycle. Confirm no previous guest image appears.
4. During networking, unplug/reconnect Ethernet; toggle Wi-Fi; interrupt router/hotspot; disconnect/restart/background/foreground iPad; idle; apply MainActor stress; use Wi-Fi + Ethernet; switch selected interface; send 100 invalid pairing attempts and malformed traffic; then reconnect the paired iPad.
5. For printing, test normal print, printer offline, paper/ribbon out, user cancellation, long AppKit callback, and process restart after uncertain submission. Confirm unknown submission requires operator verification and never auto-duplicates.
6. Force quit during capture, finalizing, rendering, upload, and print. Test low disk, queue persistence failure/corruption, and restart reconciliation.
7. Scan guest QR on Wi-Fi-only, Ethernet-only, both-active, VPN, and VM-adapter configurations. Test local HTTP and public HTTPS separately, plus 20–50 concurrent guest downloads.
8. Capture evidence for each outcome, device/iPadOS version, interface selection, queue/manifest state, and any operator recovery action.
