# v1.4.3 Release Hardening Invariants

These are release invariants. A helper-level test does not satisfy an invariant
unless it exercises the production path.

- No visible authoritative state change occurs before required durable state is committed.
- A manifest never points to content that an uncommitted replacement can overwrite.
- Workspace files are not deleted while a job can still read or write them.
- A stale in-memory manifest never overwrites a newer durable manifest.
- Socket failure detection, invalidation, and reconnect scheduling do not require MainActor progress.
- A client action mutates only the exact authoritative state occurrence for which it was issued.
- Only one logical physical print operation is active at a time.
- A print timeout is unknown, not proof that AppKit ended the operation.
- Healthy asset backpressure does not close a healthy control connection.
- Failed transactions restore the prior working state or enter an explicit recoverable error state.
