# PRC-PhotoBooth v1.4.3 Physical Release Validation

Use this checklist with the production Mac, Sony ZV-E10, Canon SELPHY CP1500,
primary event iPad, event Wi-Fi, Ethernet adapter, and hotspot fallback. Add the
older iPad Pro 9.7 if it is available. Record evidence for every result; do not
mark a subsystem passed unless its production path was exercised.

## Release gate

- [ ] Record the tested app version, build, Git SHA, macOS/iPadOS versions, Mac
      model, camera model, printer, event, and iPad model.
- [ ] Confirm the Xcode 27 CI run is green for the exact tested Git SHA,
      including Mac tests, iPad tests, release builds, generic-device build,
      packages, and the stable macOS lane.
- [ ] Confirm the test is configured as **Production Pipeline**, with the real
      camera, coordinator, storage, finalization queue, QR renderer, iPad
      transport, selected delivery path, and selected print intervals.
- [ ] Set a target of at least 500 sessions where practical and keep the booth
      running continuously for 4–6 hours.
- [ ] Record the soak run ID, session count, photos per session, cloud choice,
      auto-cleanup choice, and print interval before starting.
- [ ] Confirm the UI states that test sessions are isolated from the live
      gallery and event statistics. If cloud is enabled, record the temporary
      route pattern `/s/soak/<runID>/<sessionID>/`.
- [ ] Take a baseline screenshot or export of the production gallery and event
      statistics before the run.

## End-to-end run

- [ ] Start the soak and verify each cycle uses the actual camera and iPad
      workflow. Do not substitute Synthetic Benchmark results.
- [ ] Confirm captured photos, strip rendering, gallery persistence, local
      delivery, optional cloud publication, and selected print intervals use
      their production jobs.
- [ ] For cloud output, decode the QR from the rendered strip. Confirm it is
      exactly the run-scoped route, then fetch that exact URL and verify HTTP
      200 with a non-empty `strip.png` response.
- [ ] Confirm the normal event gallery never shows soak images while the run is
      active, including when automatic gallery approval is enabled.
- [ ] Confirm event history, totals, and statistics do not include soak
      sessions while the run is active or after it ends.
- [ ] Record completed, failed, stopped, and cancelled cycles; physical capture
      attempts and successes; recovery attempts; reconnects; queue failures;
      print outcomes; cloud/QR verification; and cleanup warnings.
- [ ] Record memory baseline, peak, and final values; capture/render/queue
      latency p50, p95, p99, and maximum; compare the first and last run windows.

## Network fault matrix

For each action, record the time, action, visible stage, recovery duration, and
whether an operator had to intervene.

| Done | Fault injection | Expected result |
| --- | --- | --- |
| [ ] | Unplug and reconnect event Ethernet | Booth stays available; paired iPad reconnects without app restart. |
| [ ] | Turn event Wi-Fi off and on | No crash or stale control slot; delivery returns on the selected route. |
| [ ] | Interrupt and restore the router | Trusted iPad reconnects after the network returns. |
| [ ] | Interrupt and restore the hotspot fallback | Route changes are visible and recovery does not require restarting the app. |
| [ ] | Force a DHCP address change for the iPad | Stored-secret HMAC authenticates the iPad at its new address. |
| [ ] | Background and foreground the iPad | Active session state recovers and the next session can start. |
| [ ] | Toggle iPad Wi-Fi off and on | Control and preview channels recover. |
| [ ] | Restart the iPad | Persisted peer trust reconnects after app launch. |
| [ ] | Sleep and wake the Mac if used operationally | Listener and trusted reconnect recover without a manual app restart. |
| [ ] | Apply a controlled 10–15 second MainActor stall | Listener, authentication, heartbeat, and trusted reconnect continue while UI updates wait. |
| [ ] | Make at least 30 invalid pairing attempts | Attempts are throttled; the real paired iPad remains able to prove its stored secret. |
| [ ] | Make at least 100 hostile pre-auth connections, including slow Hello, random IDs, spoofed trusted IDs with bad HMAC, and rotating source endpoints | Admission stays bounded; after the finite flood ends, the real iPad authenticates. Record any rejection or cooldown. |
| [ ] | Reconnect the trusted iPad during the hostile flood | The real peer completes HMAC and secure-channel setup within the agreed recovery bound. |

## Camera privacy and recovery matrix

Before starting, leave old images on the camera card. Keep the camera clock
intentionally offset for the clock-offset case. For every case, verify the
returned media belongs to the current capture attempt and never to the prior
guest.

- [ ] Successful capture with old images already present.
- [ ] Failed capture that creates no new camera object.
- [ ] Retry Receive after a transfer timeout.
- [ ] Retake after a failed or rejected capture.
- [ ] Unplug and reconnect the camera between guests.
- [ ] PTP timeout and safe quarantine/reset workflow.
- [ ] Sony PC buffer behavior.
- [ ] Camera clock offset behavior.
- [ ] Hundreds of old images on the card.
- [ ] Explicit Guest A / Guest B check: Guest B never receives Guest A's image.

## Canon SELPHY CP1500 print matrix

Use the configured production print intervals and record the queue job ID and
operator-visible outcome for each case.

- [ ] Normal print produces exactly one physical copy.
- [ ] Cancel before submission produces no copy and remains cancelled.
- [ ] Cancel or lose the callback after submission; mark the result unknown and
      resolve it manually before any further print attempt.
- [ ] Paper-out condition does not cause an automatic duplicate.
- [ ] Ribbon-out condition does not cause an automatic duplicate.
- [ ] Printer unavailable, then restored; uncertain submissions stay operator
      controlled.
- [ ] Slow AppKit completion callback does not trigger another physical copy.
- [ ] Force-quit after an uncertain print, relaunch, and verify recovery never
      resubmits it automatically.

## Persistence and crash recovery matrix

Force terminate the app at each point, relaunch, and record the recovered
session state, job state, route visibility, and any operator action required.

- [ ] During camera capture.
- [ ] During guest review.
- [ ] Immediately after finalization-plan persistence.
- [ ] During strip rendering.
- [ ] During gallery persistence.
- [ ] During cloud upload/publication.
- [ ] During physical print submission or unknown completion.
- [ ] During soak route depublishing and local cleanup.
- [ ] During remote cloud cleanup.

## Cleanup and post-run checks

- [ ] With auto-cleanup enabled, confirm the run-scoped cloud alias and files
      are removed after successful verification.
- [ ] If remote cleanup fails, confirm the report says **Completed with
      warnings**, retains a retryable diagnostic, and identifies the remote
      failure.
- [ ] Confirm retained soak diagnostics are clearly marked and excluded from
      normal event gallery/history/statistics.
- [ ] Confirm normal session routes and customer files remain intact.
- [ ] Re-run cleanup for the same run and confirm it is safe to repeat.
- [ ] Compare the production gallery and event statistics with the baseline;
      no soak image or session count may appear.
- [ ] Attach the complete run report, screenshots/photos of hardware setup,
      representative queue/route evidence, and operator notes.
